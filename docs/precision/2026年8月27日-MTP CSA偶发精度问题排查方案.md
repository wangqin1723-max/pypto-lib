## 1. 事件卡片

### 1.1 症状

`models/deepseek_v4_flash_mtp/decode_csa.py` 在 A2/A3 设备上偶发通过 `kv_cache` 校验、但未通过 `x_out` 的 `ratio_reldiff` 校验。

| 事件 | 代码范围 | device | 坏点数 | 坏点率 | 首个坏点 |
|---|---|---:|---:|---:|---|
| [原始 PR 失败](https://github.com/hw-native-sys/pypto/actions/runs/33036547578/job/98400778713?pr=2421) | PyPTO PR #2421 | 10 | 2405 / 131072 | 1.8349% | flat 20481 = `[t1,hc1,d1]` |
| [后续 PR 失败](https://github.com/hw-native-sys/pypto/actions/runs/33048240456/job/98438094227) | 同一 pypto-lib 源码窗口 | 10 | 2366 / 131072 | 1.8051% | flat 4096 = `[t0,hc1,d0]` |

### 1.3 数值合同

`x_out` 的现有校验为：

- 单点 relative-diff 阈值：`4e-3`。
- 允许超限点比例：`0.8%`。
- 坏点中的最大 relative-diff 必须小于 `1`。

前三次失败的坏点比例为 `1.8051%～2.2079%`，已经单独违反计数门槛。即使放免某个近零点的 hard cap，也不能使这些运行通过。

### 1.4 当前执行边界

当前只授权和计划进行诊断，不做以下动作：

- 不放宽 `x_out` 阈值。
- 不移植 D-Spark 的近零豁免。
- 不在没有具体缺边证据时增加 dependency 或 delay workaround。
- 不在捕获真实失败现场前开启大规模 args dump。
- 不在没有稳定 bad fixture 和 known-good/bad 端点时启动 commit bisect。

## 2. 失败指纹

### 2.1 空间分布

标准 fixture 使用 `B=4`、`S=2`、`T=8`：

| token | position | 角色 |
|---|---:|---|
| `t0` | 8192 | 8K 长上下文，完整多 sparse-block 路径 |
| `t1` | 8193 | 8K 长上下文，完整多 sparse-block 路径 |
| `t2..t7` | 0, 1, 2, 3, 3, 4 | 短上下文对照组 |

三次失败都从 `t0` 或 `t1` 开始，并最先在 `hc=1` 跨过最终阈值。`t0/t1` 具有 5 个有效 sparse block；短上下文 token 只走轻路径。

### 2.2 数值形态

- 原始失败的首个 actual/golden 都是正常量级，不是接近零的符号翻转。
- 第三次失败虽然包含一个会触发 hard cap 的点，但其 `2.2079%` 坏点率本身也已超限。
- `hc=1` 的 post gate 在当前 fixture 中通常大于其他 HC 通道，因此它最先跨阈值可以是上游误差被放大的结果。

因此，“首个最终坏点位于 `hc=1`”支持 HC 通道放大，但不能单独证明 `hc_post` 是第一处分叉。

## 3. 事实、推断与证据边界

| 观察事实 | 支持或削弱什么 | 不能证明什么 |
|---|---|---|
| 三次 FAIL 均为约 1.8%～2.2% 坏点 | 属于相似的输出误差形态 | 不能仅凭比例断言三次根因完全相同 |
| 首个坏点都在 `t0/t1`、`hc=1` | 支持长上下文重路径相关和 HC 放大 | 不能直接归因于 merge 或 `hc_post` |
| 首个坏点数值不是近零 | 排除 D-Spark 近零翻转对这些首发点的解释 | 不能排除张量其他位置存在近零值 |
| 同一源码窗口既 PASS 又 FAIL | 支持输入敏感或运行时非确定性 | 不能单独证明存在 race |
| device 10、11 都失败且也都曾通过 | 削弱固定坏卡假设 | 不能排除更细的设备状态或 runner 条件 |
| SWA、HCA 在 CSA 前通过 | 削弱全局设备故障和简单前序污染 | 不能证明 CSA 的所有输入 cache 都正确 |
| 10 次 fresh compile 的实际 binary hash 相同 | 在已测环境中削弱普通编译非确定性 | 不能替代真实 CI binary 的归档 |
| 本地 48 个 seed 均 PASS | 说明当前本地环境未覆盖失败条件 | 不能证明随机输入与失败无关 |
| 延长 cache writeback 与 qk_pv 后仍 PASS | 削弱已测试 RAW/完成边假设 | 不能排除其他边、漏写或插桩扰动 |

本案统一采用三层表述：看到的是“事实”，事实支持的是“推断”，能够排除到什么程度由“证据边界”限定。

## 4. CSA 定位地图

### 4.1 主数据流和旁路

```text
x_hc
├─ hc_pre ───────────────→ post, comb ───────────────────────┐
│      └─ x_mixed                                             │
│          └─ rms_norm                                        │
│              ├─ qkv_proj_rope ─→ q, kv                     │
│              │                    └─ ori KV writeback ─┐     │
│              ├─ ratio-4 compressor ─→ cmp_kv ─────────┤     │
│              └─ indexer ─────────────→ idx_topk ───────┤     │
│                                                        ▼     │
│   q + updated ori_kv + updated cmp_kv + idx_topk              │
│      └─ qk_plan → qk_pv → sparse_blk_* → merge_norm           │
│         → o_packed → grouped o_proj → attn_out ───────────────┤
│                                                              ▼
└──────────────────────────────────────────────────────────→ hc_post → x_out
```

`idx_topk` 不是 sparse attention 的唯一动态输入；`q`、本轮更新的原始 KV 和压缩 KV 都绕过它。`attn_out` 也不是 `hc_post` 的唯一动态输入；`post` 和 `comb` 从 `hc_pre` 旁路进入。

### 4.2 完整边界原则

判断一个消费者是第一处分叉前，必须比较它的全部可变边界输入，而不是只挑一个代表 tensor。

| 边界 | 消费者 | 必须检查的可变输入 | 固定输入如何处理 |
|---|---|---|---|
| C0 | `hc_post` | `attn_out`、`post`、`comb` | `x_hc` 来自冻结输入，校验快照 hash |
| C1 | sparse attention | `q`、相关原始 KV 写入行、相关压缩 KV 行、`idx_topk` | block table、position、window、weights 等来自冻结输入 |
| C2 | `qk_pv` | `cmp_sparse_indices`、`sparse_bias`、`valid_block_mask`、`qk_order` | q/KV 已在 C1 验证 |
| C3 | `merge_norm` | `sparse_blk_mi/li/oi` | rope/sink 来自冻结输入或已验证派生量 |
| C4 | grouped o-proj | `o_packed` | `wo_a/wo_b/scale` 来自冻结输入 |
| C5 | `proj_b_act` | `partials`、`act_scale_dq` | weight scale 来自冻结输入 |

“输入相同”不要求每个低精度中间量逐 bit 等于 torch；确定性数值分支应使用匹配的阶段数值合同和误差分布判断是否在该边界发生显著跃迁。

### 4.3 正确的粗粒度切分

```text
x_out 失败
├─ 比较 C0：attn_out、post、comb
│  ├─ 三者都符合阶段合同，x_out 分叉 → hc_post
│  ├─ post/comb 先分叉 → 回溯 hc_pre
│  └─ attn_out 先分叉 → 检查 C1
│
└─ 比较 C1：q、相关 ori_kv、相关 cmp_kv、idx_topk
   ├─ q 先分叉 → qkv_proj_rope 上游
   ├─ ori_kv 写入行先分叉 → KV writeback 上游
   ├─ cmp_kv 先分叉 → ratio-4 compressor 上游
   ├─ idx_topk 先分叉 → indexer，并检查 score near-tie
   └─ C1 全部符合合同，attn_out 跃迁 → 进入 sparse attention 内部
      └─ C2 → C3 → C4 → C5
```

## 5. 假设账本

状态含义：

- `open`：现有证据不足，仍需判别实验。
- `downgraded`：已有反证降低概率，但尚未构成完整排除。
- `rejected`：在本案当前症状和环境范围内已有直接反证。
- `confirmed`：单变量实验同时改变首处分叉和最终失败，并通过负对照。

### H1：长上下文 sparse 路径发生输入敏感的数值放大

- 机制：8K token 需要 indexer top-k、5-block QK/PV 和 online-softmax merge；小的上游数值变化经过 BF16/INT8 输出投影与 HC gate 后跨过最终阈值。
- 预测：冻结的失败输入在同一 binary 上结果稳定；C1 输入符合合同，而 C2～C5 中出现第一个稳定的误差分布跃迁。
- 支持：失败只从 `t0/t1` 开始；短上下文 token 未成为首发点；失败值不是近零；真实 bad fixture 在同一 binary 和跨卡重放中 40/40 复现完全相同的错误 actual。
- 新支持：G4 已把完整链条闭合到 func 14。func 14 仅有 rel-L2 `2.45e-7` 的 FP32 尾差，却先改变 6 个 QR scale，再形成 6 个相邻 BF16 ULP、5 个 query INT8 off-by-one 和 token 1 的 4 个 top-k 成员替换；该选择变化随后集中放大到 qk_pv sparse block 4、`o_packed`、`attn_out` 和最终 2929 个坏点。
- 反证：无针对“存在输入敏感放大”本身的反证；尚未完成只改变一个数值机制的 NPU 干预，因此不能把具体修复路径标成 confirmed。
- 判死实验：完整 C1 输入正确，并且 sparse 内部所有边界与 golden 都保持同等误差预算，或同一输入的 actual 非确定变化。
- 状态：`open`；置信度：高。G4 已达到机制链的 L2 定位，G5 受控干预后才能升级为 `confirmed`。

### H2：indexer top-k 边界换位导致下游放大

- 机制：第 512/513 名附近的 score 很接近，设备和 torch 的小数值差使候选换位，随后选取不同压缩 KV。
- 预测：失败 actual 的 `idx_topk` 与 golden 不同，且差异集中在 top-k 边界；配对 score 能解释换位。
- 支持：真实 bad fixture 已直接观察到 token 1 的 top-k 集合替换 4 个成员；actual-only 为 `[330,842,1354,1866]`，golden-only 为 `[418,930,1442,1954]`。完成态 device score 由 host `torch.topk` 选出完全相同的 device 集合，plan 也逐位忠实复制；query INT8-only replay 足以重现该集合。
- 反证：这不是 top-k 实现错误或未决 tie：device cutoff margin 为 `0.026453`，top-k 与 plan 对各自输入完全自洽。换位是上游 query 数值差异跨过离散选择边界的结果。
- 判死实验：失败现场中 `idx_topk` 与阶段 golden 完全一致，或换位候选下游结果等价。
- 状态：作为“放大机制”已由直接证据支持；作为“top-k 算子缺陷”在当前 fixture 上 `rejected`。

### H3：调度、缺依赖、漏写或未初始化导致非确定结果

- 机制：消费者在生产者完成前运行，或读取未完全覆盖的 GM 区域，使同一输入产生不同 actual。
- 预测：同一 input、同一 binary 的 actual SHA 或 PASS/FAIL 形态发生变化；明确的单边序列化或完整初始化能够稳定改变结果。
- 支持：同一源码既 PASS 又 FAIL；失败跨 seed、device 和 runner 条件出现。
- 反证：已验证多条 cache RAW；延长 cache writeback 和 qk_pv 未触发失败；真实 bad fixture 在 device 1 和 device 3 上各 20/20 产生同一 actual；所有后续消费者都能从同次 completed inputs 精确或在数值合同内重放；func 14 的 atomic target 16 份 before snapshot 均为全零，after padding 也全零，未见漏初始化或部分覆盖。
- 判死实验：真实失败输入在原 binary 上样本内稳定，且所有生产写覆盖、依赖和边界值均一致。
- 状态：对当前 frozen fixture 的根因 `rejected`；不外推到其他未观察输入。

### H4：grouped o-proj 是第一处分叉

- 机制：`act_scale_dq`、INT8 partial 或分组累加中的数值/发布问题只污染部分 token/channel。
- 预测：`o_packed` 符合合同，而 `act_scale_dq`、`partials` 或 `attn_out` 首次跃迁。
- 支持：输出投影确实继续放大 token 1 的上游差异，但只属于传播路径。
- 反证：func 47/48/49/50 的 direct dump 与 actual-input replay 已闭环；actual `o_packed` 足以逐位预测全部下游 INT8/INT32，首个完成态差异最终上移到 func 14。
- 判死实验：C4/C5 边界定位到其他阶段，或失败 actual 中 o-proj 中间量均符合合同。
- 状态：作为第一处分叉 `rejected`；作为下游放大环节保留在因果链中。

### H5：`hc_post` 是第一处分叉

- 机制：HC gate、comb 或 residual 组合自身计算错误。
- 预测：`attn_out`、`post`、`comb` 都符合阶段合同，但 `x_out` 首次跃迁。
- 支持：最终首发集中在 `hc=1`。
- 反证：`hc=1` 的 gate 本身更大，能自然放大任何上游误差；一个共享 BF16 `attn_out` 反演值可在最大 `2.3842e-7` 误差内重构全部 actual `x_out`，且解释 `99.9999999512%` 的最终误差能量。G4 直接 dump 进一步显示 residual 逐位正确、`post/comb` 全部通过数值合同、`attn_out` 已明显失败；现有 `golden_hc_post` 用四个 dumped 输入逐位复现了 dumped `x_out`，最大误差为 0。
- 判死实验：`attn_out`、`post` 或 `comb` 已先分叉。
- 状态：`rejected`（针对当前冻结 bad fixture）。直接 device cut-set 和 after 输出构成反证；没有观察到 GM scalar coherency、索引、乘加或写回导致的额外误差。不外推到未观察的其他 fixture。

## 6. 调查原则

### 6.1 每个实验只回答一个问题

实验开始前必须写出处理组、对照组、固定变量和结果分支。不能同时增加 dependency、提升 dtype、改变 merge 顺序后，再把 PASS 归因于其中任意一个改动。

### 6.2 先冻结现场，再观察中间量

- seed 是重建线索，不是权威现场；随机调用顺序变化会使同一个 seed 生成不同 fixture。
- `data/in` 和 `data/out` 固定输入与 golden，但不能替代失败 device actual。
- source commit 相同不等于 binary 相同；判断同 binary 必须复用 `runtime_dir` 或校验实际 binary hash。
- 在没有完整失败包时，不进入中间量 dump。否则插桩后得到的 PASS 无法与原失败建立同一事件关系。

### 6.3 区分观察、定位和因果证明

| 证据等级 | 含义 |
|---|---|
| L1 观察 | 发现相关模式，例如错误集中在 `t0/t1` |
| L2 定位 | 比较完整消费者边界，找到第一处误差跃迁 |
| L3 因果 | 单变量干预按预测改变第一处分叉和最终输出，负对照不受影响 |
| L4 修复 | 冻结失败用例和输入分布回归都通过，原阈值不变 |

“错误集中在某模块的输出”最多是 L1；“第一个坏点在该模块之后”达到 L2；只有受控干预闭环才能称为根因。

### 6.4 保持数值合同

- kernel 与阶段 golden 必须对齐 op 顺序、dtype、cast mode、量化和 merge 顺序。
- INT32 top-k index 先严格比较；出现差异后再使用 score-paired 语义判断 near-tie。
- FP32/BF16 中间量先看 `error_distribution` 的 rel-L2、cosine、阈值分布和分位数，不把首个 bit 差异自动当成根因。
- 不使用放宽最终阈值来替代定位。

### 6.5 显式记录观测扰动

每次实验必须标明是否开启 args dump、dep-gen、swimlane、PMU，是否改变输出 ABI、buffer 生命周期、task 数量或依赖。现象在插桩后消失时，结论是“实验受到扰动”，不是“问题已经修复”。

## 7. 总决策树与阶段门

```text
G0 归一化症状
└─ G1 捕获完整失败现场
   └─ G2 同 input + 同 binary 重放
      ├─ actual SHA / PASS-FAIL 变化 → 分支 A：非确定性问题
```

## 8. G1：捕获完整失败现场

### 8.1 计划改动

第一轮只增加 host 侧诊断，不修改 kernel DSL：

1. 在 `build_tensor_specs()` 之前增加可选 `--seed`，并无条件打印 `torch.initial_seed()`。
2. 增加 `--save-data`，转发给 `run_jit(save_data=...)`。
3. 失败时打印 `RunResult.work_dir`。
4. 保持原 comparator 的 PASS/FAIL 逻辑不变，失败时补充：
   - `[token,hc]` 坏点计数；
   - 每 token 最大 relative diff；
   - 完整 device `x_out` 的 SHA256。
5. 补充受控的 failure-only actual 保存能力，将所有顶层 actual output 写入 `data/actual/`。若修改 Golden Harness 公共行为，应同步 `run`/`run_jit`、单测和公开文档；不能在方案中假设现有 `save_data` 已经具备该能力。
6. 归档 runtime/build 目录，或至少记录所有实际执行 binary 的 SHA256。

### 8.2 CI 集成约束

- 原 PyPTO job 会重新 clone pypto-lib main；诊断提交必须能被该 job checkout，或由临时 workflow pin 到指定提交。
- 仅为 CSA 诊断运行开启数据保存，避免整个模型 sweep 都写大型快照。
- artifact 上传必须发生在 runner 清理 `build_output/` 之前。
- 最好在原失败 step 后、原 runner 和原设备租约仍有效时，立即复用同一 `runtime_dir` 和 `golden_data` 做少量重放；跨 runner 重放属于后续对照，不替代“同 binary”实验。

## 9. G2：冻结现场并判断确定性

### 9.1 主实验

固定以下变量：

- `data/in` 和 `data/out`。
- 原失败 `runtime_dir` 或 hash 完全相同的 binary。
- runner、device、runtime 配置和环境变量。

先在原 runner/原卡重复，随后才做异卡和跨 runner 对照。每次记录：

- PASS/FAIL。
- 各 actual output SHA256。
- `x_out` 总坏点数和 `[token,hc]` 分布。
- 首个坏点和最大 relative diff。
- 是否开启任何 DFX 功能。

### 9.2 判定

| 结果 | 可下的结论 | 不可下的结论 |
|---|---|---|
| 出现两个不同 actual SHA，或 PASS/FAIL 交替 | 已证明当前现场存在非确定行为 | 尚未证明具体是缺依赖、漏写还是设备状态 |
| 20/20 actual SHA 与错误分布一致 | 当前样本内稳定，进入确定性数值分支 | 不能声称所有运行绝对确定 |
| 原卡稳定失败、异卡稳定通过 | 支持设备或环境相关 | 不能直接判定硬件故障 |
| 开启 dump 后形态改变 | 观测受到时序/布局扰动 | 不能把 dump 后结果用于否定原事件 |

## 10. 分支 A：非确定性问题

### 10.1 调查顺序

1. 列出每个可变 GM tensor 的生产者、消费者、写入范围、读入范围和 ready 边。
2. 检查每个 consumer 可读区域是否被完整初始化或写满，包括 invalid/tail 分支。
3. 检查 generated dependency graph 和 orchestration，而不是只根据 DSL 源码推断。
4. 对同一 buffer 的 reshape/view 验证实际 base、offset 和 region overlap。
5. 只有形成明确的单边假设后，才做 serialization、delay、初始化或 dependency A/B。

### 10.2 因果标准

一个 dependency 假设只有在以下条件同时满足时才能确认：

- 图中能指出缺失或错误边，或能指出确定的未覆盖读区域。
- 只改变这一条边或这一处初始化即可按预测稳定改变 actual。
- 负对照边不改变现象。
- 结果不依赖放宽数值门槛。

此前对 cache writeback 和 qk_pv 的延时实验已经记录在实验账本中；除非新失败现场指向同一边且给出新预测，否则不重复相同实验。

## 11. 分支 B：确定性数值问题

### 11.1 G3：先验证阶段 oracle

对每个准备比较的阶段，记录 kernel 与 torch reference 的：

- 运算顺序和 merge 顺序。
- 输入、累加和输出 dtype。
- 每次 narrowing cast 的位置与 rounding mode。
- INT8 量化粒度、scale、clamp 和反量化顺序。
- top-k tie/near-tie 语义。

如果 golden 与 kernel 的合同不等价，应先修 reference，并从未插桩基线重新验证；不能拿错误 golden 给 kernel 定罪。

#### 11.1.1 G3 实际结果（2026-08-27）

C0 合同审核已经通过：

- `attn_out [8,4096] BF16`：kernel 与 golden 的 block merge、inverse RoPE、per-group INT8 量化、group 0→7 反量化累加和最终 BF16 narrowing 顺序一致。A2/A3 Cube、`exp/div` 和 reduction tree 与 Torch CPU 不承诺逐位相同，因此把它作为数值 oracle，不做 bitwise 判罪。
- `post [8,4] FP32`：两边均为 `2*sigmoid(...)`，HC projection golden 专门模拟 A2/A3 split-K 累加顺序；设备 sigmoid/rsqrt 仍允许正常尾数差。
- `comb [8,16] FP32`：两边均按 `[in_h,out_h]` 布局，执行 row softmax、首次 column normalization，再做 19 轮 row→column normalization。
- `hc_post`：两边都先计算 `FP32(attn_out)*post`，再按 `in_h=0→3` 做四次独立 FP32 `mul+add`，最终完整写 FP32 `x_out`；冻结 PTO 没有把它融合成不同的 FMA 顺序。
- 冻结输入重新运行完整 Torch golden 后，`kv_cache` 和 `x_out` 与保存的 golden 逐位一致，排除了 reference 文件漂移。

无 NPU 插桩的 C0 代数检查进一步给出强分流证据：一个共享 `[T,D]` `attn_out` 偏差解释了 `99.9999999512%` 的最终误差能量；舍入到 BF16 后重新走 `hc_post`，对 actual `x_out` 的最大重构误差为 `2.38418579e-07`，没有点超过 `1e-6`。这强烈降低了 `hc_post/post/comb` 首发的概率，但它使用 golden gate 做反演，不是直接 device 中间量，不能替代 G4。

静态 lowering 还留下一个需要同次实验裁决的风险：`hc_post` 对 `post/comb` 使用直接 GM scalar dereference，生成代码未调用 DCCI；同时 orchestration 依赖 runtime 自动 RAW，没有显式 dependency 列表。前者在项目文档中属于潜在 coherency 风险，但本案生产者为设备 TSTORE，不同于文档中的 host-input 示例，因此只能记为未决线索，不能先行归因或直接加 workaround。

完整合同、源码/lowering 行号、CPU 重算和反演日志见 `build_output/_jit_attention_csa_test_20260827_220404/g3/c0_contract.md`。G3 退出条件已满足，进入 G4；下一实验一次保存 func 51 / `hc_post` 的所有 before 参数与 after 输出。

### 11.2 G4：按完整边界定位

1. 比较 C0 的 `attn_out/post/comb/residual → x_out`。
2. 若 `attn_out` 已分叉，先沿直接生产者向后倒推：C5 `partials/act_scale_dq → attn_out`，再切 C4 的 func 48 完整边界 `o_r_pad → act_scale_dq/o_r_i8_pad`；只有 quant 重放通过后才决定是否单切 func 49 或上移 func 47。这个方向的 payload 更小，而且每一刀都有明确的 producer-consumer 判定。
3. 若输出投影链输入已经错误，再比较 C1 的 `q/ori_kv/cmp_kv/idx_topk`，随后在 C2 计划元数据与 C3 block states 间细分。
4. `idx_topk` 不同时同时比较 score 边界；near-tie 换位不自动等于错误。
5. 每次只增加当前完整边界所需的 level-1 dump tag，并记录插桩是否改变现象。

阶段浮点量使用 `error_distribution` 判断第一个显著误差跃迁；index、mask、order 和 block metadata 使用严格语义检查。

## 12. G5：根因机制证明

定位到第一个边界后，先写预测，再做一次单变量干预。

确定性数值分支的候选干预：

- 只提升一个中间量或一次累加的 dtype。
- 只修正一个 cast 的 rounding mode。
- 只冻结 top-k index，区分“选择变化”和“同选择下数值变化”。
- 只改变一个 merge 顺序，并同步阶段 golden。
- 只绕过一处量化边界，保留其他路径不变。

非确定性分支的候选干预：

- 只序列化一个明确的 producer-consumer 边。
- 只完整初始化一个疑似未覆盖区域。
- 只延长一个生产者，并预测消费者是否应后移。
- 只将一个并发 writer 改为单 writer，保持数学结果不变。

确认根因必须同时满足：

1. 干预按预测改变第一处分叉，而不只是让最终测试偶然 PASS。
2. 最终 `x_out` 在原阈值下随之修复或以预测方式变化。
3. 负对照不受影响。
4. 恢复原机制后失败重新出现，或等价反向实验成立。

预测不成立时应否定或降低该假设，回到 G4；不能继续叠加第二个“修复”直到测试转绿。

## 16. 学习复盘

### 16.1 seed 不等于失败现场

seed 只能在代码、随机调用顺序、torch 版本和线程行为均保持一致时重建输入。冻结 `data/in` 才固定输入，归档 device actual 才固定失败结果，binary hash 才固定执行程序。

### 16.2 同一源码不等于同一 binary

同一 commit 可以因 toolchain、compile config 或生成环境产生不同 artifact。判断运行时非确定性时应优先在原 job 中复用同一 `runtime_dir`，随后再做跨构建对照。

### 16.3 最终首个坏点不等于第一处内部误差

`hc=1` 可能只是拥有更大的 gate，使共同的上游误差更早跨过最终门槛。定位必须沿完整数据流向上寻找第一个误差分布跃迁，而不是从最终 flat index 直接猜模块。

### 16.4 一个代表 tensor 不能切断存在旁路的数据流

`idx_topk` 相同不能证明 sparse attention 的输入都正确，因为 `q` 和两类 KV 绕过它；`attn_out` 相同也不能单独证明 `hc_post` 有错，因为 `post/comb` 是旁路输入。完整 cut-set 是模块归因的前提。

### 16.5 top-k index 不同不自动等于错误

边界 score near-tie 时，数值等价的候选可能换位。需要把 index 与 score、有效范围和下游语义配对判断；明显低分候选被选中才是强错误证据。

### 16.6 count failure 与 hard-cap failure 是两件事

近零豁免通常只影响最坏单点 hard cap。当前三次运行的坏点比例已经超过 `0.8%`，所以即使去掉一个近零点也仍然失败。

### 16.7 dump 会制造 Heisenbug

args dump、额外输出和更长 buffer 生命周期会改变 host 收集、任务时序和内存布局。dump 后 PASS 的含义首先是“观察改变了系统”，不能直接解释为原路径正确。

### 16.8 定位不是因果证明

发现某个 completed tensor 是当前第一处分叉，只能把范围收窄到它的生产边界。只有一个预先有预测的单变量干预同时改变第一处分叉、离散选择和最终 `x_out`，才足以确认具体机制。

### 16.9 “CI 偶发”不等于“冻结样本仍随机”

CI 里的 PASS/FAIL 可以来自每次 fresh fixture 不同：某些输入跨过误差门槛，另一些没有。G2 固定真实 bad input 后在两张卡上合计 40/40 得到同一错误 actual，说明当前应优先研究这个输入触发的稳定数值路径。它降低了运行间随机 race 和固定坏卡的优先级，但不能仅凭重复稳定就排除稳定调度下可重复的实现错误。

### 16.10 多路下游输出可以先做无扰动反演

当一个上游向量被多个已知不同 gate 复用时，可以用多个下游输出建立超定约束，检查误差是否落在该共享上游分量张成的子空间中。本案四路 HC 输出把 `attn_out` 的共享误差解释到 `99.9999999512%`，因此在不改变 NPU 时序的情况下显著提高了下一刀命中率。但反演依赖 golden gate，并不等于读取了 device 中间量；它只能提出强预测，不能替代完整 cut-set 的直接证据。

### 16.11 用 actual-input replay 区分“消费者算错”和“消费者传播错误”

只看到消费者输出错误时，不能立刻给消费者归因。先把同一次 dispatch 的全部 before 输入和 after 输出一起保存，再用消费者自己的 reference 重放 actual 输入：若重放逐位或在严格合同内复现 after，说明消费者是在忠实传播上游误差；若全部输入正确而 after 无法复现，才把范围锁到消费者执行/读取边界。本案 dumped `attn_out/post/comb/residual` 经现有 `golden_hc_post` 逐位复现坏 `x_out`，把 G3 的代数推断升级成了 C0 的直接边界证据。

### 16.12 下一刀不仅看二分位置，也看观测成本

理论上可直接跳到 sparse-attention 入口比较 C1，但 runtime args dump 会按 block 重复保存完整参数；大 KV cache 会显著放大 payload 和插桩扰动。已知 `attn_out` 错误后，先检查它的直接生产者 func 50，既保持完整 producer-consumer 判定，又把观测范围限制在 `partials/act_scale_dq`。边界选择应同时考虑信息增益、payload 大小和 Heisenberg 风险，而不是机械按图一次跨越最多节点。

### 16.13 “两项都显著”不等于“两项贡献相同”

单独替换一个 actual 输入后越过精度合同，只能说明该输入有能力造成显著输出变化；还要看它与 observed delta 的方向和残差。本案 partials-only 的 delta cosine 为 `0.936823`、解释 `86.9848%` 能量，而 scale-only 的 cosine 只有 `-0.0180525`、解释能量为负。两者都 FAIL，但 partials 才是主方向，scale 更像共同上游偏差带来的正交/抵消修正。选择下一边界时应结合 contract、delta cosine、energy explanation 和 interaction，不能只数 FAIL 个数。

### 16.14 可逆线性下游能提供强交叉约束，但不能冒充直接 dump

当下游是已知整数矩阵乘且权重子块非奇异时，可以从 INT32 partial 反解唯一 INT8 输入，再用未参与求解的输出通道做 exact 验证。本案全部 4096 通道都逐位闭环，把“func 49 输出像随机错误”降到很低，并预测 direct `o_r_i8_pad` 应是什么。但这个 INT8 仍是数学推断；若 func 49 读错地址，它也可能等价于乘了另一组合法 INT8。只有下一刀直接保存 func 48 after，才能把代数证据升级成完整边界证据。

### 16.15 共享 tensor 的多任务 dump 要比较 ownership，不比较整份快照

func 48 按 group 提交 8 个任务，却共同写 `act_scale_dq` 和 `o_r_i8_pad`。每个 after snapshot 的非本任务区域可能处于不同完成状态，因此 8 份完整 payload 不应被要求逐位相同。正确判法是用该 task 的 scalar `g/col_g` 确定 ownership，只比较 scale 的第 `g` 行和 INT8 的第 `g` 个 1024-column slice；其他区域只用于诊断调度状态，不进入数值 verdict。

### 16.16 第一处 bit difference 不一定是错误，但可以是放大链的起点

func 14 的 `qr_fp32` 有 7,156 个 bit difference，看起来很多；但 max abs 只有 `1.43e-6`、rel-L2 只有 `2.45e-7`，输入又逐位相同。这符合设备 Cube/split-K 与 Torch 不同累加树的正常数值尾差，不能按“第一个不相等”直接报 bug。它之所以重要，是因为后续 replay 证明这批合法尾差确实进入了 6 个 scale ULP 和多个离散边界。因此排查时要同时回答两个问题：差异是否超出阶段合同，以及它是否对最终异常具有因果传播能力。

### 16.17 多个离散边界会把微小连续误差变成结构性差异

本案不是一次突然的大误差，而是至少三次阈值化：FP32 值跨 BF16 中点、Hadamard 结果跨 INT8 半整数、score 排名跨 top-k cutoff。每一步单看都合法且稀疏，串联后却把 6 个 BF16 值变成 4 个不同 KV 候选，继而让整个 sparse block 的 attention 结果改变。遇到“上游 rel-L2 极小、最终误差很大”时，应优先画出 cast、round、argmax/top-k、mask 和路由等离散边界，而不是只搜索某个大 FP32 溢出点。

### 16.18 SPMD INOUT dump 的 before 数量由活跃子任务决定

### 16.19 反事实实验必须先确认变量真的进入 binary

第一次把 `QR_OK=1` 放在临时模块目录中但仍从原始脚本目录启动，生成的 PTO 仍含 `2048`，说明实验变量没有生效。不能只看命令行或临时源码；必须检查生成 PTO/lowering 常量，再解读 PASS/FAIL。修正为从临时目录启动 `decode_csa.py` 后，PTO 出现 `QR_K_SLICE=4096`，实验才具备因果效力。

#### G5-C：func 15 amax 顺序与 reciprocal 独立差异（2026-08-30）

func 15 的设备路径先计算 `amax(qr_fp32 * gamma)`，再乘 `inv_rms`；golden 先计算 `(qr_fp32 * inv_rms) * gamma`，再取 amax。两者在实数上等价，但 FP32 乘法的中间舍入位置不同。设备路径还使用 `recip(127 / amax)` 产生 dequant scale，而直接表达式是 `amax / 127`。这两个差异源与 func 14 split-K 无关，需要单独验证。

独立 NPU probe `build_output/csa_func15_alignment_20260830/func15_alignment_probe.py` 直接输入完全相同的 FP32 `qr_fp32[4096,1024]` 和 BF16 gamma，在同一 binary/任务中比较 deferred-amax、full-normalize-amax 和 direct-dequant 三条路径。工具链固定为 PyPTO `3e852dac`、simpler `799640e6`、PTOAS `0.57`、PTO ISA `cd4a3d3f`。首次任务为 `task_20260830_191805_157331231548`，10 轮复用 binary 任务为 `task_20260830_191832_158989712153`。

- 10 轮 sweep 中 9 轮产生真实 QR INT8 off-by-one，合计 26 个；例如 `-12 -> -13`、`21 -> 22`。这证明 amax 性能重排本身就是独立的离散翻转源。
- `recip(127 / amax)` 与 `amax / 127` 每轮造成约 `1031～1095 / 4096` 个 dequant scale 位级差异，max abs 最高 `3.72529e-9`。它不改变当次 QR INT8，但会改变后续 INT32 投影的缩放尾差。

#### G5-D：top-k 边界候选 BF16 重排原型（2026-08-30）

为验证“保留 INT8 全量粗选，只提高第 K 名附近候选的选择精度”是否可行，在 `build_output/csa_boundary_rerank_20260830/kernel_m32/` 建立隔离实验副本，正式 `models/deepseek_v4_flash_mtp/decode_indexer.py` 未修改。原型固定 `K=512、M=32`：INT8 分数先取 top-544，前 480 名直接保留；对排名 481～544 的 64 个候选复用第二次 Query INT8 量化前的 `qh_acc_gm`，将候选 C8 KV 临时转换为 BF16，计算 `BF16 Query × BF16(INT8 KV value)`，再按原合同执行 ReLU、index-head 权重求和和 `idx_kv_scale` 缩放，从 64 个候选中补选 32 个。

#### G5-F：只替换 top-k 成员的 sparse-attention 反事实（2026-08-31）

#### G5-G：候选重排正式化尝试与否证（2026-08-31）

#### G5-H：第一次 QR INT8 与第二次 qh INT8 的分层因果实验（2026-08-31）

为验证 G5-G 中“canonical 边界必须前移到第一次 QR INT8 之前”的判断，在独立 detached worktree `build_output/csa_prequant_rerank_20260831/repo/` 中做三级递进实验。正式工作区 kernel 未修改。环境固定为 PyPTO `3e852dac`、simpler `799640e6`、PTOAS `0.57`，在 A2/A3 device 0 上运行，最终 CSA comparator 保持 `diff_thd=4e-3、pct_thd=0.8%、max_diff_hd=1`，未放宽阈值。

第一级只在 `qkv_proj_rope` 输出第一次 QR INT8 前的 BF16 `qr_prequant`，然后在 indexer 中按原合同再做一次 per-row INT8 量化。`qkv_proj_rope` 单算子的 `qr_prequant/q/kv/qr/qr_scale` 全部 PASS，indexer 单算子的 score/top-k 也 PASS；但完整 CSA `seed=20260844` 仍 FAIL，为 `2611/131072` 个坏点（1.9920%）。这证明“导出后重新量化”不会恢复共同连续输入：device 与 golden 的 `qr_prequant` 仍保留 Cube/累加顺序造成的微小差异，重新经过同一个离散量化边界仍可翻转。

第二级真正绕过第一次 QR INT8：indexer 直接消费 `qr_prequant`，将 indexer `wq_b` 按 per-output scale 反量化为 BF16，执行 `BF16 Query × BF16 Weight -> FP32`投影；后续 qh INT8 score 和 top-k 保持不变。已知 `20260844`、固定历史坏 seed `12802700365775099988` 与反向样本 `10270709133758572702` 全部 PASS。但 fresh `20260831..20260850` 只有 17 PASS / 3 FAIL：

| 失败 seed | 坏点数 | 坏点比例 |
|---:|---:|---:|
| `20260834` | 1960 | 1.4954% |
| `20260840` | 2906 | 2.2171% |
| `20260842` | 3082 | 2.3514% |

这证明第一次 QR INT8 是真实且可消除的放大源，但不是唯一的离散边界。

第三级在第二级之上继续绕过第二次 qh INT8：Hadamard 后 Query 以 BF16 进入 score matmul，C8 KV 按 per-position scale 反量化并转 BF16，再计算 `BF16 KV × BF16 Query -> FP32 score`；kernel 与 golden 同步使用该实验合同。第二级的三个 fresh 反例全部转为 PASS；完整 fresh `20260831..20260850` 为 20/20 PASS，再加两个历史样本，共 22/22 PASS。

| 实验合同 | fresh 20 seed | 两个历史样本 | 判定 |
|---|---:|---:|---|
| 导出 `qr_prequant` 后重做原 INT8 | 未扫；`20260844` 仍 FAIL | 未扫 | 重建同一离散边界无效 |
| 绕过第一次 QR INT8 | 17 PASS / 3 FAIL | 2/2 PASS | 第一边界是真实贡献者，但不完整 |
| 同时绕过 QR INT8 与 qh INT8 score | 20/20 PASS | 2/2 PASS | 两层离散放大链可解释当前样本 |

G5-H 结论：**当前 CSA FAIL 不是 top-k 排序实现单点错误，而是 `qkv_proj_rope` 连续尾差先后经过第一次 QR INT8、第二次 qh INT8/score 两个离散边界，最终在 top-k cutoff 附近变成 KV 成员替换。**分层 A/B 实验已证明两个边界都有机制贡献，但第三级是高开销的全量 BF16 因果原型，且同步改变了 kernel/golden 的 score 合同，不是可直接合入的修复。

正式方向有两类：

1. 保持现有模型语义：让 kernel/golden 在第一次量化前共享可复现的 canonical Query/score 合同，并只对 cutoff 小窗口做统一高精度重打分；该重打分必须同时绕过 QR INT8 和 qh INT8，不能再使用已分叉的 `qh_acc_gm` 作为起点。
2. 接受新的选择语义：由模型侧正式定义 BF16/canonical score、tie-break 与候选窗口合同，kernel/golden 同步修改并做模型质量和性能回归。

不建议放宽 CSA 最终阈值：G5-F 已证明四个 cutoff 成员替换可解释约 99% 的最终误差能量，它不是可忽略的连续尾差。当前原型只用于定位，未做性能验收、跨卡和更大 seed sweep，不满足附录 D 的正式修复关闭条件。

#### G5-I：leader 批准后的 CSA comparator 门限调整（2026-08-31）

应 leader 可接受当前离散边界引起的输出差异，正式工作区仅调整 `models/deepseek_v4_flash_mtp/decode_csa.py` 的 `x_out` comparator，不改任何 kernel 逻辑。保留绝对差阈值 `4e-3`，将超出该阈值的元素比例从 `0.8%` 提高到 `3%`，并将最大相对误差 hard cap 从 `1` 调整为 `2`。该调整仅作为当前 CSA 的显式测试合同，不改全局 `ratio_reldiff` 和其他模型。

在 A2/A3 device 0、同一编译产物上验证：`20260844` 、`20260840`、`20260842`、历史坏 seed `12802700365775099988` 以及反向样本 `10270709133758572702` 均 PASS；`kv_cache` 仍使用原严格 comparator。其中三个 fresh 反例原始坏点比例为 `1.4954%/2.2171%/2.3514%`，最大观测相对误差为 `1.53`，因此这组门限包含已观测范围但仍保留硬上限。

G5-I 的性质必须明确：这是 leader 承认后的测试合同调整，不是消除 QR/qh INT8 离散翻转的修复。新增注释会标记该原因，避免后续将放宽误当成精度根因修复。

2. 对当前失败现场完成确定性/非确定性分类。
3. 找到第一个完整消费者边界分叉。
4. 用单变量实验确认具体机制。
5. 修复在真实 bad fixture、fresh fixtures、长短上下文和跨卡回归中通过。
6. 最终阈值未放宽，未依赖诊断 dump 才能 PASS。
7. 问题已明确归属 pypto-lib 或通过 style/pin/own-code gate 后归属上游。
