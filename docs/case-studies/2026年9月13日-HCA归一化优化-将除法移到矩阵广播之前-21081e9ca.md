## 优化准则

**优先在广播前的小标量或小向量上完成归一化，再将归一化因子广播到矩阵。
同一个分母被多处使用时，优先考虑只计算一次倒数并复用。**

对于矩阵 `X[M, N]`，如果分母 `d[M, 1]` 在每一行的所有列之间共享，则有：

```text
Y[i, j] = X[i, j] / d[i]
        = X[i, j] * inv_d[i]，其中 inv_d[i] = 1 / d[i]
```

倒数只需对 `M` 个逻辑元素计算一次，再沿 `N` 列复用。
这是一条优先尝试的优化准则，是否保留仍由浮点精度和实测耗时决定。

## commit 21081e9ca 实际做了什么

修改对象是 `models/deepseek_v4_flash_dspark/decode_hca.py` 中的
`hca_stream_merge_pack_publish` kernel。

原始注意力和压缩注意力的输出分别记为 `A` 和 `B`，形状都是 `[16, 512]`。
合并系数 `alpha`、`beta`，以及计入 attention sink 项后的分母 `d`，
形状都是 `[16, 1]`。

```text
修改前：output = (alpha * A + beta * B) / d
修改后：output = (alpha / d) * A + (beta / d) * B
```

以上系数与矩阵相乘时，都采用按行广播。
这个提交先对系数做归一化，再用归一化后的系数执行原有的矩阵广播乘法：

```python
stream_alpha_norm = pl.div(stream_alpha, stream_denom)
stream_beta_norm = pl.div(stream_beta, stream_denom)
stream_o_scaled = pl.row_expand_mul(stream_o, stream_alpha_norm)
stream_cmp_o_scaled = pl.row_expand_mul(stream_cmp_o, stream_beta_norm)
stream_output = pl.add(stream_o_scaled, stream_cmp_o_scaled)
```

最终的矩阵广播除法被消除。除法处理的对象从一个 `16 × 512` 矩阵，
缩小为两个各有 16 个元素的向量：**逻辑元素数从 8192 降到 32，变为原来的 1/256**。
这个比例只描述除法涉及的逻辑元素数，不代表硬件指令数或整体加速比；
实际执行还受向量布局、填充、指令重复次数及其他计算的影响。

该提交仍然使用了 **两次向量 `pl.div`**，尚未显式计算并共享一次倒数。

## 下一步候选优化：共享一次倒数

可以尝试将两次系数除法替换为：

```python
stream_denom_inv = pl.recip(stream_denom)
stream_alpha_norm = pl.mul(stream_alpha, stream_denom_inv)
stream_beta_norm = pl.mul(stream_beta, stream_denom_inv)
```

后续按行广播乘法和输出加法保持上文的写法。
这样只计算一次 16 元素向量的倒数，再供两个系数复用。
**本次调查尚未验证这个候选方案的精度及额外性能收益。**

## 后端实现与数值限制

不能将“所有硬件都没有除法指令”或“所有 DIV 都会自动变成 RCP + MUL”
作为这项优化的通用依据。

本次核对了 `wq3` 实际选中的 PTO ISA，版本为
`a8040450238f162985d8b596fbebeb54bfba2bf5`：

- `include/pto/npu/a2a3/TDiv.hpp` 和 `TRowExpandDiv.hpp` 调用 `vdiv`。
- `include/pto/common/pto_instr.hpp` 中，`TRECIP` 通过 `TDIVS(dst, 1, src)` 实现。
- `include/pto/npu/a2a3/TDivS.hpp` 的浮点“标量除以向量”路径，
  先用标量填充分子，再调用 `vdiv`。

因此，当前后端实现不能证明 `pl.recip` 会选择专用且更快的近似倒数指令。
共享倒数仍可能减少重复的分母处理，但也会增加系数乘法，
并可能改变依赖关系或临时存储需求，需要针对生成结果实测。
这些源码映射也不足以推断芯片内部算术单元的物理实现。

将除法移入系数，或用乘倒数替换除法，都可能改变浮点舍入结果。
采用近似倒数的实现还可能引入额外误差。
官方 [Ascend C Reciprocal 文档](https://www.hiascend.com/document/detail/zh/canncommercial/850/API/ascendcopapi/atlasascendc_api_07_0028.html)
明确说明了精度限制，并建议在需要更高精度时使用 Div。
这项 API 提示不代表本次核对的 PTO `TRECIP` 路径采用了相同的近似实现。

后续实验继续使用 `wq3` 环境和 TP=4，回放相同的固定输入与 golden 数据，
验证所有输出。根据实际输入范围，检查分母范围以及零值、非有限值的处理。
修改源码后单独编译新的构建产物，再以相同的 100 轮计时、5 轮预热配置，
比较关闭 profiling 后最快 rank 的中位耗时。
精度通过且该指标改善后，再保留修改。

#### 1. 优先迁移 HCA 的合并系数归一化

TP=1 当前仍先合并两个输出矩阵，再做一次矩阵广播除法：

```text
当前：output = (alpha * A + beta * B) / d
候选：output = (alpha / d) * A + (beta / d) * B
```

`A`、`B` 的 tile 均为 `[16, 512]`，`alpha`、`beta`、`d` 均为 `[16, 1]`。
这个变换把除法涉及的逻辑元素数从 8192 缩小到 32，保留原有的两次矩阵广播乘法，
消除最后一次矩阵归一化。它与 `21081e9ca` 的计算模式直接对应，因此优先验证。

先单独测量两次向量除法的版本，再把共享倒数作为独立候选：

```text
inv_d = 1 / d
alpha_norm = alpha * inv_d
beta_norm = beta * inv_d
output = alpha_norm * A + beta_norm * B
```

两种版本都可能改变 FP32 舍入结果，不能用 TP=4 的精度结果代替 TP=1 验证。
逻辑元素数的变化也不等于硬件指令数或整层加速倍数。

#### 2. 验证 SWA、CSA 的输出广播除法

两处当前均使用 `pl.row_expand_div(m_oi, n_denom)`，可尝试：

```python
n_denom_inv = pl.recip(n_denom)
n_normalized = pl.row_expand_mul(m_oi, n_denom_inv)
```

SWA 的实际 `H_TILE` 是 32，CSA 是 16；两者 `HEAD_DIM` 都是 512。
每个分母被同一行的 512 个元素共享，符合“先在小向量上求倒数，再广播”的条件。
这里用一次矩阵乘法替换矩阵除法，不能像 HCA 系数变换那样完全消去最后的矩阵运算。

三者的输出归一化都处于 attention 输出到 O 投影的依赖链上，
因此是值得优先验证的整层性能候选；是否处于实际执行关键路径、能节省多少时间，
仍需后续测量确认。

#### 3. 再验证共享 Sinkhorn 与量化尺度

`comb_sinkhorn` 包含初始行 softmax 和 20 轮列归一化，后 19 轮还包含行归一化。
可以分别尝试在三个 TP=1 入口启用已有 `row_recip` 分支，
以及将每轮四次使用同一个 `col_sum` 的除法改为一次倒数加四次乘法。
先独立比较行、列变换，再决定是否组合，避免无法归因。
这一部分 tile 较小，整层收益还取决于它与其他任务的重叠和核心竞争情况。

Q 投影和 CSA indexer 的反量化尺度化简，只减少小向量上的倒数计算，
优先级低于 attention 输出归一化。验证时保留 `amax` 下限、量化倍率、
数据类型与舍入流程，并检查反量化误差是否影响最终输出；CSA 还需要检查 TopK 结果。
当前 CSA 的 TP=1 入口调用完整的 indexer query 路径，
不能套用多卡入口在短上下文下跳过部分评分计算的判断。

TP=1 的 [decode_o_proj.py](https://github.com/hw-native-sys/pypto-lib/blob/1d4bcebb773c9fd5d02c767672361398bc5b6a23/models/deepseek_v4_flash_dspark/decode_o_proj.py)
在 `decode_o_proj_tp1` 中已经直接计算
`g_scale_dq = pl.mul(g_amax, 1.0 / INT8_SCALE_MAX)`，这处不重复修改。
